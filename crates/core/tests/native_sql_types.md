# Checked PostgreSQL domain types

The application pins SQLx and the direct `sqlx-postgres` driver to 0.8.6. Only the direct driver's normal dependency enables `uuid` and `chrono`; the SQLx facade keeps those features disabled. This avoids its optional MySQL feature edges and the vulnerable inactive RSA package they bring into the lockfile. The additional timezone/platform dependencies come from the PostgreSQL driver's published Chrono `clock` feature. No upstream source changes or advisory exceptions are required.

Domain identifiers derive transparent `sqlx::Type`, delegating to the driver's native UUID implementation. `Timestamp` manually delegates PostgreSQL type information, compatibility, array type information, and encoding to Chrono's `DateTime<FixedOffset>`, while enforcing a calendar boundary during decoding. Queries use SQLx's documented `query_as!` field wildcard aliases (`"field!: _"`) and bind overrides (`value as _`). The proc-macro host graph therefore needs no UUID/Chrono mapping. PostgreSQL still checks the query, parameter arity and native parameter/result types during preparation. Rust requires native `Type`/`Encode`/`Decode` implementations, and wildcard result fields retain runtime SQL type compatibility checks. Bind overrides intentionally bypass the macro's separate inferred Rust parameter type comparison; use domain-typed function parameters at query boundaries.

`native_sql_types.rs` contains a checked constant query with native `uuid` and `timestamptz` columns and parameters, without casts to text. Its live test verifies the returned identifier, timestamp instant, microsecond precision and serialization; independently incorrect UUID and timestamp binds must each return no row. The committed descriptor was generated by the application's 0.8.6 macro against PostgreSQL, rather than synthesized.

## Calendar boundary

Stored timestamps decode only within calendar years 1 through 9999. Binary timestamps are checked before upstream date arithmetic: PostgreSQL's signed microseconds from 2000-01-01 must lie in the inclusive range -63082281600000000 through 252455615999999999. Text results are parsed through the existing driver codec, then checked by calendar year. Every decode failure returns one static message (`crates/core/src/timestamps.rs`); native diagnostics and timestamp values are discarded.

The early binary check also rejects positive/negative infinity and distant finite PostgreSQL dates before SQLx 0.8.6's unchecked epoch-plus-duration calculation can panic. Native Chrono decoding itself accepts finite BC and year-10000 values, which is why delegated decoding alone is not enough. Literal year zero is rejected by PostgreSQL before decoding. PostgreSQL's `0001 ... BC` represents astronomical year zero and exercises the row-decoding refusal.

The test connection is set to UTC, and SQLx's native binary `DateTime<FixedOffset>` decoder returns offset zero; UTC is the only supported session time zone ([limits](../../../docs/rust/limits.md#timestamps-and-time-zones)). The checks cover binary and simple-query text protocols, boundary scalar binding, array binding and invalid array elements, sanitized failures, upstream finite-date controls, and the checked SQL metadata query. This preserves `FromStr`'s Chrono parse-error API, public wrapper construction, encoding, and ISO/Serde serialization. HTTP timestamp formatting remains separate from stored audit serialization.

## Running

Set `CANNERY_SQL_TYPE_TEST_DATABASE_URL` to an isolated database migrated with `cannery migrate` (its name must be `conformance_` followed by 24 lowercase hexadecimal characters) and run the ignored test:

```sh
cargo test --locked -p cannery-core --test native_sql_types -- \
  --ignored --nocapture
```

Ordinary builds use `SQLX_OFFLINE=true`. To regenerate or check descriptions, set `SQLX_OFFLINE=false` and `DATABASE_URL` for a disposable migrated database, then use the helper described in `tools/sqlx-cli/README.md`.
