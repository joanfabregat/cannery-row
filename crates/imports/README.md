# Historical imports library

`cannery-imports` reads reviewed historical bundles and imports them through a single owned PostgreSQL transaction. The bundle format is documented in [docs/import.md](../../docs/import.md). The `cannery import` command calls `read_bundle(root, limits, contracts)`, then `run_import(pool, bundle, options, context)`. `ImportOptions` supplies the project slug, optional science document, dry-run flag, and explicit missing-entry policy. `ImportContext` supplies the embedded contract validator and independent project-field, science rendering, and JSON budgets, and a finite statement timeout. There is no default validation profile or application installation. `Plan` reports the immutable bundle digest, created/unchanged counts, state/track/authority counts, gaps, and retained missing entries; `describe` supplies CLI-ready reporting lines.

The library verifies unique verified user emails and existing researcher memberships for deciders, validates the pinned science/scorer/validator registrations, resolves controls/relations/policies and measurement citations, and retains the source history's dates and imported provenance. It creates external artifacts, historical tester/evaluator evidence, review cases and human decisions, reports, immutable ledger entries, and system-attributed CLI audit events. It never creates live jobs, leases, uploads, or tester-verified measurements. Existing projects retain their title and description. A project-scoped advisory transaction lock serializes imports; the project's ordinary number allocation remains locked within the same transaction. Changed immutable entries and missing entries without `allow_missing` refuse the entire import. `allow_missing` retains history and reports it. Dry runs execute the same constraints and writes, then roll back.

File reads use directory descriptors and `openat` with `NOFOLLOW`, checking regular files without following symlinks. Report paths must identify a visited UTF-8 Markdown file inside the bundle, exactly once, and reports are hashed before the bundle digest is computed. UTF-8, NUL, orphan reports, file/byte/depth/node limits, and duplicate keys are checked before database work. Hidden entries are ignored; visited symlinks are refused, including hidden symlink leaves. Contents of ignored hidden directories are not traversed. File names and JSON pointers appear in diagnostics; supplied values and driver error text do not.

## Parsing and limits

YAML aliases and merge keys are refused instead of expanded. JSON must use strict JSON syntax, and all files use string-keyed, finite JSON-compatible values. Parser features for includes and property interpolation are disabled; YAML tags cannot execute code or fetch files. Required caller limits also bound total bundle bytes, nesting and nodes, and numeric text is limited to 1,024 characters. `cannery import` uses 20,000 files, 8 MiB per document, 256 KiB per report, 32 MiB total, depth 200, and 200,000 nodes. Equal object content is hashed as compact UTF-8 JSON with recursively sorted keys. Numeric lexical representations remain in file digests; immutable ledger comparisons use exact decimal values, preserving replay across PostgreSQL JSONB normalization. Evidence timestamps are normalized to UTC RFC 3339; imported ledger documents retain their original date strings. Invalid contracts produce value-free file/pointer diagnostics.

The YAML parser is `serde-saphyr` 0.0.29, with deserialize-only features. Its [release notes](https://github.com/bourumir-wyngs/serde-saphyr/releases/tag/0.0.29) document hardening and fuzzing work; its [options](https://github.com/bourumir-wyngs/serde-saphyr/blob/0.0.29/src/de/options.rs) provide the duplicate, merge, alias and resource controls used here.

The library uses the production SQLx pool/transaction architecture and checked queries. `cannery import` supplies the server's research validation policy, bounded bundle/science reads, a 30-second default statement timeout (`--statement-timeout-seconds`) and settled pool closure on success, refusal or signal cancellation. A refusal prints one `cannery import: ` JSON problem per line on stderr, with exactly `file`, `pointer` and a value-free `message`, and exits 1.

`ImportContext::statement_timeout` is required and accepts 1 millisecond through 5 minutes. The exported `DEFAULT_STATEMENT_TIMEOUT` recommends 30 seconds for CLI callers; `MAX_STATEMENT_TIMEOUT` is 5 minutes. The library sets PostgreSQL's transaction-local timeout before acquiring the advisory lock. This bounds each statement, including a canceled lock waiter, rather than the whole import; callers retain responsibility for pool and network timeouts.

## Verification

`cargo test -p cannery-imports` checks the example bundle's YAML/JSON digest equivalence and reports, duplicate/alias rejection, resource bounds, symlink containment and orphan reports. `cargo clippy -p cannery-imports --all-targets --all-features -- -D warnings` and `cargo fmt --all --check` cover the complete crate.

`tests/history.rs` is an ignored database test, run in CI by `ci/database-tests.sh` against a fresh migrated database. It imports the complete published example, checks counts/provenance/authority/no-live-job records, and compares complete raw rows from all affected tables around dry runs, changed/missing entry refusal, replay, membership refusal, an injected late audit failure and cancellation. It exercises concurrent imports, append-only constraints, and a real advisory-lock waiter aborted before retry.
